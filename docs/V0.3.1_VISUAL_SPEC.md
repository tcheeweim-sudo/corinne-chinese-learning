## Visual direction

The existing app is functionally accepted but visually too prototype-like.

The target is:

- warm
- soft
- calm
- polished
- child-friendly without looking preschool-like
- plush / clay-inspired
- spacious
- consistent with the approved Tiger and Tiger House art

Avoid rainbow UI, neon colours, harsh borders, strong drop shadows, noisy backgrounds, or excessive decoration.

## Colour system

Use the approved artwork as the final visual reference. A practical starting palette is:

- page background: `#FFF8F2`
- elevated card: `#FFFDFB`
- primary peach: `#F5B7A8`
- warm orange: `#E8A15C`
- warm brown text: `#604238`
- muted pink: `#F3C3CB`
- pale sage: `#D6E3C9`
- pale blue: `#D9EAF0`
- soft border: `#EFDAD0`

These may be adjusted slightly to match the actual approved PNGs, but do not introduce an unrelated colour system.

## Home screen

Keep exactly four child-facing destinations:

1. Today's Mission
2. Practice 听写
3. Revision
4. Tiger House

Today's Mission remains the primary hero action.

Use `tiger-home.png` as the main emotional anchor.

Goals:

- clearer hierarchy
- more whitespace
- softer cards
- more coherent buttons
- visible coin balance
- subtle grown-up link
- calmer and more premium presentation

Do not add additional navigation or product features.

## Mode-specific Tiger use

Suggested semantic mapping:

- home / welcome: `tiger-home.png`
- positive feedback: `tiger-happy.png`
- completion reward: `tiger-celebrate.png`
- retry / support: `tiger-encourage.png`
- questions / revision: `tiger-thinking.png`
- writing / study: `tiger-writing.png`
- quiet / idle: `tiger-sleeping.png`
- Tiger House: `tiger-house.png`

Use selectively. Do not place a large Tiger on every screen if it crowds learning content.

## Tiger House composition

Use `house-room-empty.png` as the room background.

Layer purchased items individually through the existing Tiger House state and slots.

Use `tiger-house.png` with `object-fit: contain`; do not crop aggressively.

Ribbon and hat are wearable overlays. Use the alignment reference as implementation guidance. Preserve the current equip logic.

Do not use the fully furnished room reference as the live scene.

## Typography and components

Retain readable system-safe fonts unless there is a compelling reason to introduce a bundled font.

Improve:

- heading scale and spacing
- body line height
- card padding
- button height and corner radius
- chips and pills
- progress bars
- inputs and parent controls
- success / empty states

Use warm brown text instead of near-black where contrast remains accessible.

## Responsiveness

Must remain strong on:

- 390 × 844
- 768 × 1024
- 1024 × 768

The visual refresh must not reduce handwriting area or crowd functional controls.

Decorative art should scale down first, not learning content.

## Icons

From the approved masters derive and wire:

- 192 × 192 app icon
- 512 × 512 app icon
- 512 × 512 maskable icon
- favicon as appropriate

Keep the Tiger face safely inside maskable-icon safe bounds.

Use the approved coin icon in the visible coin balance where practical.

## Offline and deployment

All runtime visual assets must be staged by GitHub Pages and cached by the service worker.

Reference-only design files do not need to be cached for runtime.

Increment the service-worker cache version after asset integration.

## Acceptance criteria

V0.3.1 succeeds if:

1. All V0.3 learning functionality remains unchanged and passes existing tests.
2. Placeholder Tiger graphics are gone from normal runtime screens.
3. Home feels visually coherent with the approved Tiger artwork.
4. Tiger House uses the approved empty room and individual purchasable items.
5. Wearable accessories align acceptably with Tiger House Tiger.
6. App icons come from the approved master.
7. No broken asset links exist.
8. Phone and tablet layouts remain usable.
9. Offline use still works after initial install.
10. The app feels like one designed product rather than a functional prototype.
