# V0.3 Product Specification

## Goal

V0.3 should restore useful choice without returning to the complexity of V0.1.

The app should support four clear child-facing destinations:

1. Today's Mission
2. Practice 听写
3. Revision
4. Tiger House

Today's Mission remains the default daily habit. Practice 听写 supports school spelling preparation. Revision supports broader exam preparation using MOE curriculum, archived 听写 and weak-item data. Tiger House remains the reward loop.

The interface must stay simple enough for a Primary 1 child to use independently.

## Product principles

- Keep the home screen simple and child-friendly.
- Mission is a default option, not the only learning mode.
- Practice 听写 should feel like real spelling preparation.
- Revision should support exam periods without exposing parent-level complexity to the child.
- Reuse the V0.2 mission, mastery, migration, Hanzi Writer, offline and Tiger House foundations.
- Keep learning logic transparent.
- Final visual assets should be replaceable independently from application logic.

## 1. Home structure

Show four clear cards only.

### A. Today's Mission
- Primary / largest card.
- Roughly 5 minutes.
- Guided adaptive flow.
- Continue using the V0.2 3-focus-item and maximum-2-writing-character defaults unless changed later through a single configuration point.

### B. Practice 听写
- Focused preparation for the active school spelling set.
- Allow access to archived 听写 sets later.
- Child should be able to choose a short or full practice session.

### C. Revision
- Broader lesson and exam preparation.
- Pull from MOE recognition characters, writing characters, past 听写 and weak items.
- Child-facing choices should remain simple.

### D. Tiger House
- Spend coins.
- Decorate room.
- Equip Tiger accessories.

Parent access remains small/subtle.

## 2. Today's Mission

Preserve the V0.2 guided path:

Tiger intro
→ See/hear
→ Listen/recognise
→ Write
→ Recall
→ Reward

Purpose:
- daily habit
- low friction
- mixed practice
- adaptive weak-item recurrence

Do not rebuild this flow unless required for shared components.

## 3. Practice 听写

Practice 听写 should support two child-friendly modes.

### Study mode
Purpose: learn before testing.

For each selected item:
- show Chinese
- play audio
- show pinyin
- show simple meaning if useful
- allow character-by-character writing practice
- allow replay

### Test mode
Purpose: simulate school spelling more closely.

For each item:
1. play the item audio
2. do not show Chinese or pinyin before the attempt
3. prompt the child to write
4. support character-by-character handwriting input using the existing Hanzi Writer infrastructure
5. reveal/check after the attempt
6. allow retry for mistakes
7. track first-attempt result separately from eventual completion

The answer must not be displayed before the attempt in Test mode.

### Session-size choices
Keep simple:
- Practice 3
- Practice 5
- Practice all

If the active set contains fewer items than the selected count, use all available items.

### Set selection
V0.3 must support the active current 听写.
Architecture should also support archived sets without redesign.

Recommended child flow:
Practice 听写
→ Current 听写 card
→ Study or Test
→ choose 3 / 5 / all
→ practice
→ result/reward

Avoid exposing dates, lesson IDs or data-source details on the child screen unless useful.

## 4. Revision

Revision is for broader exam preparation.

### Child-facing choices
Show only:
- Quick Revision
- Full Revision
- Weak Words

Suggested defaults:
- Quick Revision: 5 items
- Full Revision: 10 to 15 items depending on available content
- Weak Words: items currently identified as weak

### Revision content pool
Revision may draw from:
- MOE recognition characters
- MOE writing characters
- active and archived 听写
- weak items
- recently incorrect items

### Activity mix
Recognition content can use:
- listen and choose
- character/meaning recognition
- matching

Writing content should use:
- Hanzi Writer
- stroke-order support
- recall before reveal where appropriate

Do not add many game types in V0.3.

## 5. Parent revision controls

Parent view should allow exam-preparation configuration without exposing this complexity to Corinne.

Add a concise Revision Settings section.

Allow:
- lesson range, e.g. Lessons 1 to 16
- recognition / writing / mixed
- include current 听写
- include archived 听写
- session size
- emphasis on weak items

Use sensible defaults.

Persist settings locally.

Do not create cloud accounts or parent authentication.

## 6. Curriculum architecture

Continue the three-layer content model:

### A. MOE curriculum
- Primary 1 standard Chinese
- lesson number
- volume 1A / 1B
- recognition characters
- writing characters
- source metadata

V0.3 architecture should support the full P1A/P1B curriculum.

Do not require the whole curriculum to be manually entered before V0.3 can run. Additional lessons can be added progressively.

### B. School 听写
Each set should support:
- stable ID
- label
- test date
- lesson mapping where known
- active/archive status
- items
- pinyin
- meaning
- audio path

### C. Corinne mastery
Continue tracking recognition and writing separately where practical.

Revision selection should use existing mastery data rather than create a second scoring system.

## 7. Rewards

Coins should be available from all meaningful practice modes, but avoid coin farming.

Rules:
- Today’s Mission keeps the existing daily anti-farming logic.
- Practice 听写 and Revision should reward completed meaningful attempts, not repeated taps.
- Replaying the same completed item indefinitely must not generate unlimited coins.
- Keep one spendable currency: coins.

Use Tiger House as the main spend destination.

## 8. Navigation and complexity control

Do not recreate V0.1's multi-tab complexity.

Home should contain four destination cards only.

Inside each mode:
- one clear next action
- minimal settings
- obvious return home control

Parent-only configuration belongs in Parent View.

## 9. Visual system

Final Tiger artwork is being produced separately.

V0.3 must continue using replaceable asset paths.

Expected Tiger assets may include:
- tiger-home
- tiger-happy
- tiger-celebrate
- tiger-encourage
- tiger-thinking
- tiger-writing
- tiger-sleeping
- tiger-house

Expected house assets may include:
- bed
- pillow
- rug
- lamp
- plant
- picture
- basket
- ribbon / hat

Do not block functional development on final artwork.

Keep placeholders/fallbacks until approved assets are supplied.

## 10. Audio

Continue the V0.2 audio architecture:
1. bundled approved local audio
2. Mandarin TTS fallback
3. visible graceful failure

Practice 听写 Test mode depends heavily on reliable audio.

Do not claim Ting Xie Test mode is production-ready on Samsung until audio is physically verified.

## 11. Offline

All core V0.3 functionality should continue to work offline after initial installation, except any browser TTS behavior that depends on installed device voices.

Cache:
- app shell
- curriculum data
- active/archived set data used by the app
- Hanzi Writer and required character data
- final Tiger/house assets when supplied
- approved local audio when supplied

## 12. Migration

Preserve existing V0.2 local progress.

Do not reset:
- coins
- purchases
- Tiger House ownership/equipment
- streak
- mastery
- writing history
- completed sessions
- existing mission progress where still valid

Add versioned migration only if the V0.3 schema requires it.

## 13. Parent metrics

Keep metrics concise.

Add useful mode-level visibility such as:
- Today’s Mission sessions
- 听写 practice attempts
- first-attempt Ting Xie accuracy
- Revision sessions
- weak items
- writing repetitions
- active lesson / revision scope

Do not turn Parent View into a large analytics dashboard.

## 14. Testing

Retain all V0.2 regression coverage.

Add tests for:
- four-card home structure
- Mission remains functional
- Practice 听写 Study mode
- Practice 听写 Test mode hides answer before attempt
- 3 / 5 / all session sizing
- archived-set architecture
- first-attempt Ting Xie tracking
- no reward farming
- Revision Quick / Full / Weak selection
- parent revision settings persistence
- recognition vs writing revision filtering
- V0.2 progress migration
- offline caching
- Tiger House persistence
- day rollover
- audio fallback
- Samsung-facing audio remains flagged until device verification

## 15. Out of scope

Do not add in V0.3:
- OCR
- AI-generated exercises
- cloud sync
- accounts
- leaderboards
- social sharing
- ads
- real-money purchases
- complex mini-games
- free-form room editing
- Primary 2 curriculum

## Acceptance criteria

V0.3 succeeds if:

1. Corinne can understand the four home choices without adult explanation.
2. Today's Mission remains a low-friction ~5-minute option.
3. She can intentionally practise the current 听写 beyond the daily mission.
4. She can do broader revision during exam periods.
5. Parent controls can narrow revision scope without cluttering the child UI.
6. Existing V0.2 progress and Tiger House state are preserved.
7. The app still feels simple, gentle and coherent rather than feature-heavy.
